# What is in this repository, and what has to be fetched

This repository is the private master copy of the exhibit. **A fresh clone on
another laptop runs the app as it was left** — the code, the voice, the
classifier, the settings, the accounts and the venue's corrected waste photos
are all committed.

That is a deliberate choice (2026-11-17): losing the laptop should cost a
`git clone`, not a week of re-building. It is a private repository holding one
board's credentials — do not publish it.

## Committed

```
uc/                       the ESP32 firmware
web/backend/              the FastAPI server
web/frontend/             the dashboard
shared/intents.json       what Sara understands, in all three languages
models/piper/             Sara's voice — engine, phonemes and all four models (293 MB)
models/waste/             the MobileNet classifier (13 MB)
models/waste-resnet50/    the classifier that actually serves (91 MB)
models/whisper/whisper-server   the speech-recognition server binary
data/village.db           the village's own state: settings, accounts, history
data/waste-samples/       the venue's corrected photos (1134 files, 197 MB)
.env                      device address, token, whisper path, port
uc/include/village/secrets.h    Wi-Fi, OTA password, device token
```

`data/waste-samples/` is the one directory that cannot be re-created: each
photo is an item the classifier got wrong, filed under what it really was. It
is what a future model is retrained on.

## Not committed, and why

| What | Size | Reason |
| --- | --- | --- |
| `models/whisper/ggml-base.bin` | 142 MB | **GitHub refuses any file over 100 MB** |
| `models/whisper/ggml-small.bin` | 466 MB | same |
| `models/whisper/ggml-large-v3-turbo.bin` | 1.6 GB | same |
| `data/waste-captures/` | 322 MB | the rolling log of every crop the classifier judged; it grows with use, and the corrected photos were already extracted into `data/waste-samples/` |
| `data/cache/`, `data/logs/`, `data/run/` | 26 MB | rendered speech (regenerated by speaking), logs, PID files |

The whisper weights are the only thing a new machine must download:

```bash
./scripts/download_models.sh      # ggml-base.bin + builds whisper-server if needed
```

`ggml-base.bin` alone is enough to run the exhibit; it is the model this
deployment uses (`VILLAGE_WHISPER_MODEL` in `.env`). The larger models are
alternatives, not requirements — see `docs/operation.md` for the measured
quality of each.

## A second copy anyway

git protects against a lost laptop, not against a lost GitHub account or an
accidental rewrite of history. `./scripts/backup.sh` writes a full second copy —
the whisper weights, the crop log and a **point-in-time snapshot** of the
database — to another disk:

```bash
./scripts/backup.sh /media/usb/village     # or any path on another disk
./scripts/backup.sh --dry                  # say what it would copy, copy nothing
```

It mirrors with `rsync --delete`, so a second run copies only what changed. The
database is copied with SQLite's own backup API rather than `cp`: a live
database has a write-ahead log, and a plain copy can miss the most recent
writes.

## Restoring on another laptop

```bash
git clone git@github.com:syammohanvs/village.git
cd village
./scripts/setup.sh                  # first time only: Python env + node modules
./scripts/download_models.sh        # the whisper weights, ~142 MB
./scripts/launch.sh
```

`./scripts/setup.sh` is only needed while the Python environment or
`node_modules` are missing — both live outside git because they are re-installed,
not restored. It creates them beside the checkout (`.venv`,
`web/frontend/node_modules`) and installs both `web/backend/requirements.txt`
(the API) and `requirements-waste.txt` (the classifier: `torch` is a ~200 MB
download the first time). It needs `python3-venv`; the script says so if it is
missing.

That is the whole restore. Sign in with the account in `.env` — `mahi$haru` /
`village` on this exhibit, `admin` / `village` on a fresh database.

Two things are machine-specific and may need a look:

- `.env` names this laptop's WSL virtualenv (`VILLAGE_VENV=/home/ubuntu/.venvs/aivillage`).
  A clone usually has no such directory, so the scripts fall back to `.venv`
  beside the checkout (`scripts/venv.sh`); you only have to edit the line if you
  keep environments somewhere else on purpose.
- `VILLAGE_DEVICE_URL` points at the relay on the Windows host, whose WSL
  address changes per boot. `./scripts/relay.sh ensure` (which the start
  scripts run) repairs it.
